Lab 5 Report
For this lab, I added variables, assignments, and block scope to Viper.

Variables use var name = value; or var name; to declare them. Variables can be read with their name and changed using name = value;.
Using a variable before declaring it gives a runtime error. A variable with no initializer starts as nil. Declaring the same name twice in one scope gives a runtime error, but the name can be reused inside another block.
I used a list of dictionaries to store the variables. The program checks the current block first, then outer blocks. Variables created inside a block are removed when that block ends. Assignments change the closest existing variable with that name. This is similar to Lox.

I updated main.py, parser.py, ast_nodes.py, and evaluator.py. The scanner and AST printer from the previous labs did not need changes.
Run the tests from the folder containing main.py:

python main.py test/lab5/runtime_errors.lox
python main.py test/lab5/syntax_errors.lox

Test 2
Input:
var a = "global a";
var b = "global b";
var c = "global c";
{
var a = "outer a";
var b = "outer b";
{
var a = "inner a";
print a;
print b;
print c;
}
print a;
print b;
print c;
}
print a;
print b;
print c;
Expected output:
inner a
outer b
global c
outer a
outer b
global c
global a
global b
global c
Actual output:
inner a
outer b
global c
outer a
outer b
global c
global a
global b
global c
Result: Pass
The first three lines are printed from the inner block. It finds a inside the inner block, b in the outer block, and c globally. After the inner block ends, the next three lines use the outer a and b and the global c. After the outer block ends, the last three lines use the global variables.
